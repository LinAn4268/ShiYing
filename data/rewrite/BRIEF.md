# 拾影网页文案改写 · 语气规范（所有改写代理共用）

## 一、任务
把「拾影」摄影入门网站的正文文案按下面的语气规范重写。**大体内容、结构、事实不变，只换语气和表达。**

## 二、绝对不能改的东西
1. `id`、`title`（章名、小节名、条目名）、`tag`（理论/实操/提示）、`section`、`chapterId`、`chapterTitle` —— 这些是目录骨架，**逐字保持原样**。
2. 数组长度：`steps` 的条数、`mistakes` 的条数、`keywords` 的条数、`sections` 与 `items` 的个数，**一条都不能增删**。
3. 所有事实：参数（f/1.8、1/125 秒、ISO 100、18% 灰、ND16、24mm…）、器材名称、物理规律、因果关系、限定条件。**数字与原意必须一致**，不得为了顺口改小改大，不得新增没把握的说法。
4. JSON 结构：字段名与嵌套层级不变；`steps` 原本是对象 `{title,params,desc}` 就还是对象，原本是字符串就还是字符串（按你拿到的原文结构走）。
5. `principle` 里的段落分隔用 `\n`，段落数量不变。

## 三、语气规范（重点）
1. **亲切自然**：用「你」的视角说话，像坐在旁边讲，不端、不打官腔；不用「本文」「笔者」「综上所述」。
2. **画面感**：多写具体名词、动作和场景（「雨后墙角的水洼」「把镜头拧到 35mm」），少堆「高效、强大、完美」这类空词。
3. **节奏**：长短句交替。结论用短句，解释用中长句；一段只说一件事。
4. **适度修辞**：比喻、拟人、设问服务于理解，点到为止。可以写「慢门像给时间按了暂停键」这类**辅助解释**，但不能用比喻替代定义、不能暗示错误因果。
5. **术语**：首次出现保留规范说法，紧跟一句大白话解释（如「景深，就是画面里看着清楚的那段距离」）。通俗解释不能顶替正式定义。
6. **活泼等级**：概念解释 2.5–3 级（清楚 + 有点画面），操作步骤 2 级（步骤化、少修辞），纯参数说明 1.5 级（克制准确）。
7. **禁止**：标题党、绝对化（最/第一/100%/必看/封神）、网络烂梗、卖萌、emoji、连续排比、感叹号堆砌、「在当今时代」「随着社会发展」这类空开场；不得编造数据、案例、来源、用户评价。

## 四、各字段怎么写
- `intro`（章导语，80–120 字）：先说这章解决什么困惑，再给一个带画面的入口。保持 80–120 字。
- `summary`（本章小结）：3–5 句，把本章几条原理串成一句话能记住的结论，别复述目录。
- `practice`（练习建议）：1–2 句，具体到「拍什么、改哪个变量、拍几张」，可执行。
- `text`（三级标题下正文，100–160 字）：2–4 句。第一句给结论或场景，第二三句讲原理和用途；允许一次比喻，不要术语堆叠。
- `lead`（详解导语，40–80 字）：用一个具体疑问或场景把人拉进来，末句点出这条要解决什么。
- `principle`（原理，180–320 字，2–3 段）：先给结论，再讲为什么，最后落到「所以拍摄时你会怎么用」。段落间 `\n`。
- `steps`：每步 `desc` 15–45 字，动词开头，说清动作与判断标准；`title` 保持 4–6 字短标题（原样或同等长度改写，不改变步骤含义），`params` 只保留原本就有的参数信息。
- `mistakes`：每条 15–40 字，口语但准确，写「错在哪 + 会怎样」。
- `example`：一段 80–140 字的现场小场景，有光、有动作、有结果，不编造品牌与测试数据。
- `takeaway`：一句话（20–40 字），像贴在相机背面的便签。
- `keywords`：保持条数，词本身就是术语，不改写。

## 五、自检（交稿前逐条过）
- 标题、id、tag、条数是否一字未动？
- 数字与参数是否与原稿完全一致？
- 有没有新增原文没有的事实、案例、数据？
- 读起来像不像一个人在跟你讲话，而不是说明书？
- 有没有空话套话、绝对化表达、连续感叹号？
- JSON 能否 `json.load`？（用 python 校验一遍再交）
